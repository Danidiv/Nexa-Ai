## Sandbox blockers
### LM Studio
The sandbox cannot reach the user's local LM Studio service:
- `http://localhost:1234/v1/models` -> connection refused.
- `host.docker.internal` is not resolvable in this sandbox.

Therefore a real Mistral 3B generation call cannot honestly be claimed as an E2E sandbox test.

### Vite native toolchain
The uploaded artifact contained a Windows `node_modules` cache. Running it on the Linux sandbox exposed the expected cross-platform native dependency problem:
- Rollup could not find `@rollup/rollup-linux-x64-gnu`.
- esbuild reported that the installed package was for Windows, not Linux.

This is an environment/cache problem, not a generated React source error.

## v22 changes
- npm 404/ETARGET dependency failures are classified as invalid packages and are not retried forever.
- Invalid packages are routed to code repair instead of repeated npm install attempts.
- Repeated identical Vite diagnostics trigger a strategy change.
- React generation prompt explicitly forbids unnecessary third-party packages such as `react-router-dom`, `axios`, `lucide-react`, chart libraries, and Radix packages.
- React scaffold now checks whether native `node_modules` matches the current OS/architecture before reusing it.
- The distributable ZIP excludes `node_modules`, so the target machine bootstraps dependencies for its own platform.
- Deterministic Avatar/Accordion UI resources remain in place to protect Mistral 3B from malformed basic UI primitives.

## Important honesty note
This report does **not** claim that the exact user prompt was generated by Mistral 3B and then verified in a real browser inside the sandbox. The sandbox has neither access to the user's LM Studio process nor a compatible native Vite dependency cache. The application source and repair logic were tested as far as the sandbox permits, and the cross-platform packaging issue was fixed.
